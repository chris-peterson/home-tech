# Decisions

Architecture Decision Records (ADRs) capture choices about the home tech stack — what was picked, what was rejected, and the reasoning at the time. They are append-only: when a decision is revisited, write a new ADR that supersedes the old one rather than editing the original.

## Format

Each ADR is a numbered markdown file (`0001-short-slug.md`, `0002-…`) with the following sections:

- **Status** — Proposed, Accepted, Superseded by [link], or Deprecated
- **Context** — What forced the decision; constraints; what was true at the time
- **Decision** — What was chosen
- **Consequences** — What this enables, what it costs, what becomes harder
